# AngoMall 全栈工程版

基于用户上传的 AngoMall_V19.html 重新组织为前端 + FastAPI + SQLite 的单体项目。保留深绿与金色品牌，重做响应式商城页面；原文件完整保留在 static/original.html，便于逐项对照。本交付是可运行、可测试的交易核心工程预览版，并非 V19 全部演示模块的生产实现。

## 运行

需要 Python 3.12。

```bash
python -m venv .venv
source .venv/bin/activate
# Windows 激活命令：.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000
```

访问 http://localhost:8000 。API 文档：http://localhost:8000/docs 。不要通过双击 HTML 运行，新界面依赖同源后端。

数据库首次启动自动创建：`data.sqlite3`。可设置 `ANGOMALL_DB` 改变位置；目标目录需存在且可写。初始化导入原文件首批 77 个示例商品和商家资料，未导入后续版本脚本动态扩展的数据。原始 Kz 价格优先采用，美元商品按示例汇率 920 换算为整数 Kz，仅用于演示。原型中无库存的跨境商品初始化为示例可订量 100。

## 创建账号

买家在页面注册，密码至少 10 位。页面不能切换身份或自授管理员权限。

在服务器终端创建商家及管理员，密码通过隐藏输入读取，不设默认管理密码：

```bash
python manage.py merchant@example.com --role merchant --shop 1 --name 'Belas 商家'
python manage.py admin@example.com --role admin
```

商家账号只能处理本店订单及商品；管理员可处理所有店铺。登录后工作台入口自动出现。店铺编号可在“发现店铺”查看。

## 已打通的流程

- 注册 → 登录 → HttpOnly 会话 → 退出；密码使用 scrypt 加盐哈希，会话 24 小时到期。
- 商品关键词、分类、来源、店铺查询 → 详情 → 服务端购物车。
- 同一店铺结算 → 后端计算价格 → SQLite 事务扣库存 → 生成提货码。
- 本地待确认 / 跨境意向 → 商家确认 → 现场实际收款、输入买家提货码 → 完成。
- 未交付订单取消 → 原子回补库存；完成后申请退货 → 商家确认收到退货及已线下退款 → 回补库存。
- 后端订单状态机、买家数据隔离、店铺权限、重复请求幂等、库存并发保护和操作审计。
- 商家工作台可更新价格与可售库存；管理员审计接口 `/api/admin/audit`。

当前每次结算只支持一家店铺。跨店商品会明确提示分别结算。订单快照保存下单时的单价和商品名称，后续改价不影响旧单。确认核销码不会通过商家订单接口泄露。

跨境订单的 total 只是参考商品金额，不含运费、清关及税费。报价协商和成交金额确认仍在线下进行。系统不执行任何银行收款或退款；完成、退款按钮代表商家确认已经在线下完成相应操作。

## 验证

```bash
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
node --check static/app.js  # 有 Node 时检查前端语法
```

测试使用独立临时数据库，覆盖注册角色注入防护、越权查询/修改、下单幂等、库存扣减、商家确认、错误提货码、正确核销、售后、重复退款拦截、库存回补、跨站来源拦截、退出失效，以及两个买家并发抢购最后一件商品。当前环境运行两组测试通过，首页 HTTP 200，前端 JS 语法通过。环境没有提供 `cua_repl.js`，未完成浏览器视觉与交互测试；未将 HTTP 检查视为浏览器测试。

## Docker 部署参考

```bash
docker build -t angomall .
docker volume create angomall-data
docker run --rm -p 8000:8000 -v angomall-data:/data angomall
```

Dockerfile 已提供，容器构建未在本次环境执行。正式部署应在可信反向代理后启用 HTTPS，并设置 `COOKIE_SECURE=1`。代理须转发正确的 Host 与协议；仅在可信代理范围内配置 forwarded headers。持久化 `/data` 并定时备份 SQLite，数据文件不要放入静态目录。

## 上线前的实际缺口

这份交付不声称已经达到生产就绪或实现原型全部功能：

1. 支付商接口、签名回调验真、金额校验、真实退款与资金对账尚未接入；不得凭本系统状态当作银行凭证。
2. 跨境精确报价、运费/税费、物流追踪、采购单、仓储调拨、财务结算、商家入驻审核、优惠会员未实现。
3. 产品创建、图片上传、SKU/多仓库存、后台编辑下架后再上架的界面未实现；现有工作台可维护已上架商品的价格和可售库存。商品图片仍引用原文件第三方 URL，需替换为获授权且稳定的素材。
4. 预约自动过期释放、邮件验证、忘记密码、手机号验证码、多语言界面、通知服务与账户资料维护未实现。当前未取消订单持续占库存，需要人工取消释放。
5. 登录限速为单进程内存实现，生产应换共享限流存储；尚未增加全站限流、监控告警、备份恢复演练与负载测试。大规模交易建议迁移 PostgreSQL、引入正式迁移机制和任务队列。
6. 需真实门店、商品价格、库存、地址、服务条款及退换政策替换演示数据，再完成桌面和手机浏览器验收。

这些缺口不通过假按钮或模拟银行成功来冒充已完成。

## 使用 Render 托管（无需自备服务器）

仓库附带 `render.yaml`。在 Render 选择 New → Blueprint，连接此仓库并检查配置后部署。
该配置使用付费 Starter 服务和 1GB 持久磁盘，费用以 Render 确认页面为准；提交配置本身不会创建服务或产生托管费用。
数据库保存在 `/data/angomall.sqlite3`，HTTPS Cookie 已启用。部署完成后用 Render 分配的 HTTPS 网址访问。
请保持单实例运行；创建管理员需要在平台提供的 Shell 中运行前述 `manage.py` 命令。
